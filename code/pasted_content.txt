Build a **production-quality, responsive hackathon web application** called **AffordAI**.

## 1. PROJECT

**Project Name:** AffordAI

AffordAI is an AI-powered financial affordability assistant.

The core user journey should be:

**Enter purchase → Analyze financial situation → Get affordability decision → Understand the reasoning → See safer payment options**

The application should feel like a real **premium fintech SaaS product**, not a basic demo or generic dashboard.

---

## 2. HACKATHON PROBLEM

The project is based on this HackerRank repository:

https://github.com/interviewstreet/hackerrank-orchestrate-september26.git

### IMPORTANT

Before implementing the application:

1. Inspect the GitHub repository.
2. Understand the actual problem statement and expected inputs/outputs.
3. Identify the provided datasets, files, APIs, algorithms, and constraints.
4. Understand what the solution is expected to calculate.
5. Use the actual challenge requirements when implementing the AffordAI logic.

Do not invent a completely different problem.

If the repository contains code/data that can be reused, integrate it appropriately into the application.

# 5. PRODUCT EXPERIENCE

The main product should answer one simple question:

> **"Can I safely afford this?"**

The user should be able to enter information about a planned purchase and receive a clear financial recommendation.

Possible results:

* **Affordable**
* **Affordable with a plan**
* **Risky**
* **Not recommended**

The result should explain *why* the decision was made.

# 7. AFFORDABILITY CHECKER

Create the main AffordAI feature.

The user should be able to enter:

* Purchase name
* Purchase amount
* Purchase category
* Purchase date
* Current balance
* Monthly income
* Monthly expenses
* Existing EMI/installments
* Minimum balance they want to maintain

Primary CTA:

**Analyze Affordability**

When clicked:

1. Validate the input.
2. Calculate affordability.
3. Calculate safe-to-spend amount.
4. Determine risk level.
5. Generate a recommendation.
6. Show the result with a smooth transition.

# 8. AFFORDABILITY RESULT

Show a clear result such as:

### Affordable with a plan

Purchase:

**₹1,20,000**

Safe to spend now:

**₹32,400**

Remaining:

**₹87,600**

Then show:

* Risk level
* Current balance after purchase
* Protected minimum balance
* Expected future balance
* Recommendation

Example explanation:

> "Paying the full amount today would reduce your balance below your preferred safety level. A partial payment is safer based on your upcoming income and expenses."

Keep explanations short and easy to understand.

# 9. PAYMENT RECOMMENDATIONS

Provide meaningful alternatives:

### Pay Now

₹1,20,000

Show whether this is safe.

### Partial Payment

₹32,400 today

Show remaining amount and future impact.

### Installments

₹20,500 × 6

### Wait

Recommend a future date if waiting would improve affordability.

Clearly highlight the recommended option.
